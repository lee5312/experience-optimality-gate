# EOG 2.0 Capability Closure Contract

EOG is structurally intended to dominate invoking UOG + Ponytail + Loopy separately: capability is a superset while ordinary conceptual burden is lower.

## Closure rule

Every useful upstream capability must resolve to `absorbed`, `generalized`, `compatibility_alias`, or `external_service_reuse`. Removing a useful capability without a more general equivalent is a regression. External hosted infrastructure may remain external when EOG owns the compatible client workflow.

## Separate axes

Capability state: `absent | mapped | implemented | compatible`.

Evidence state: `unverified | contract_verified | native_verified`.

Capability closure and host verification are different questions. Lack of native evidence must not erase an implemented capability, and an inventory entry must not masquerade as native support.

## Intelligent-agent constraint

The package must not move architecture choice, search depth, abstraction, candidate ordering, or stopping judgment into a deterministic engine merely to make the method machine-checkable. Deterministic logic is justified only at integrity/authority boundaries or for exact mechanical operations. Structured records are optional representations, not workflow prerequisites.

## UOG closure

The canonical core retains experience entry/success/interaction/wait/pay/continuity/failure/recovery, durable truth, exitability, total burden, fresh evidence, non-dominated candidates, decisive unknowns, and concise/no-ceremony treatment of obvious low-risk work. EOG generalizes this with nonhuman consumers, requirements-not-mechanisms, residual responsibility, decision-relevant uncertainty, and consumer-boundary completion.

## Ponytail closure

Core minimality, causal tracing, review, audit, debt, impact, help, lifecycle, delegation, status, installation/update/remove, portability, OpenCode, Pi, Hermes, MCP fallback, regression surfaces, and `off/lite/full/ultra` depth semantics are representable through EOG. `auto` is the EOG default. Compatibility depth is task-scoped and creates no persistent mode owner.

## Loopy closure

EOG exposes discover, find, compare, craft, adapt, audit, repair, run, debrief, save, and publish client operations. It accepts native Loopy text, preserves existing LOOPS.md data, and reuses external Loop Library infrastructure rather than cloning it.

## Replacement claims

`capability_complete` means the local method can represent the useful upstream capability set without requiring the legacy local runtimes. It does not mean every third-party host has been natively observed. Host support claims remain tied to actual host evidence.
